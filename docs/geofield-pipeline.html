GPXL v2 Format

Binary Layout — lettercube.h (9,417 B → 13,865 B, ratio 1.47×) 
// Header (48 bytes)
struct Header {
    magic:      "GPXL"          // 4 bytes
    version:    2               // uint16 LE
    gp_level:   2               // uint8
    n_segments: 44              // uint32 LE
    orig_size:  9417            // uint64 LE
    xxh64:      0x300ead76...  // uint64 LE
}

// Coord Records (20B × N)
struct CoordRecord {
    seg_id:    4B  // segment index
    ring:      1B  // Goldberg ring
    wedge:     1B  // Goldberg wedge
    strategy:  1B  // ID/FLAT/DIFF/BREF/GEOM/RAW
    seed:      8B  // wallet_chunk_seed
    checksum:  2B  // xxh64 & 0xFFFF
}

// LetterCube Section (76B × N)
struct LetterCube {
    lanes[6]:  6 × 12B  // pair_id, angle, bond_state
    state:     1B        // bond bitfield
    apex:      25B       // apex data
}

// Segment Data
[length:4][raw_bytes] × N  // length-prefixed raw chunks

Note: Segment data stored as raw bytes. Compression step (Diamond Shell FLAT 2B / SPARSE 9B / DENSE 17B) pending.

Diamond Shell Distribution (GGUF Model Weights)

FLAT — 28.6%

Zero-heavy blocks. All bytes zero → stored as 2 bytes [0x00, value]. 97% savings vs 64B raw.

SPARSE — 71.1%

Quantized weight patterns. Fibo_intersect popcount ≤ 4 → stored as 9 bytes. 86% savings vs 64B raw.

DENSE — 0.4%

Complex blocks. High entropy → stored as 17 bytes. 73% savings vs 64B raw.
