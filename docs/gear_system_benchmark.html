Why 340× for small but only 1.9× for large?
For small tensors, driver overhead (~200μs per submit) dominates. For large tensors, actual data transfer time (~13ms for 15MB) becomes significant. The 340× comes entirely from eliminating 251 driver context switches.

CPU vs GPU: Why CPU Wins at Header Scanning

OperationCPU LatencyGPU LatencyWhy
Read 2B header 1.6 ns ~10,000 ns L1 cache vs PCIe round-trip
Scan 5,760 headers 9.1 us 72.8 us Sequential vs random access
Batch DMA (62KB) N/A 0.18 ms GPU excels at bulk transfer
Key insight: geo_frame_seek compresses 768B frames → 2B encoded headers (384× reduction). This makes CPU header scanning trivially fast at 1.6ns/header via L1 cache. GPU would need random access through PCIe, which is ~6,000× slower per access.
